Dependency Rules

  • Strict sequential: P0→P1→P2→P3→P4→P5→P6→P7→P8→P9→P10 (import_playbook = serial)
  • Safe to parallelize manually: P6 ∥ P7 (agent vs hub), P8 ∥ P9 (independent concerns, minor idm overlap)
  • If parallelized: P6∥P7 saves ~3m, P8∥P9 saves ~3-5m → ~35m total
  • Within P1: dns-client-setup, install-packages, clone-repos target different host groups — concurrent
  • Within P6: falco-deploy ∥ openshell-deploy (independent on agent), then demo-workloads → linux-mcp-server
  • Within P8: All 5 playbooks target different services — fully concurrent
  • P10: Validation runs last, touches all nodes

Skip / Resume

  • Skip completed phases: --skip-tags phase1,phase2,phase3
  • Run checkpoints only (verify state): --tags checkpoint
  • Run single phase: --tags phase6

Known Issues

  • siem-bridge-deploy.yaml excluded — source scripts (falco_siem_bridge.py) don't exist in repo
  • ahdapa-configure.yaml excluded — subset of oidc-configure.yaml
  • delegation-rules.yaml excluded — subset of ipa-roles.yaml (groups overlap)
  • SPIRE join token has 600s TTL — agent must start within 10 min of server token generation

Likely Break Points

  • P3 keylime-setup: swtpm SELinux policy compile fails if base policy version changes. Keylime agent registration fails if verifier TLS uses IP not hostname.
  • P4 container-deploy: registry.redhat.io pull needs podman login (terms-based). Alembic sed patch is brittle. Quadlet network prefixed systemd-. Certmonger cert can stall.
  • P5 oidc-configure: CORS blockinfile depends on exact anchor text in ipa-idp-proxy.conf. JWKS warm-up can delay API restart.
  • P6 openshell-deploy: Gateway image tag (gateway-0.0.111) pinned — breaks if cleaned from Quay.
  • P7 eda-deploy: Java OpenJDK version (java-21-openjdk-headless) — verify available in target RHEL version.
  • P9 spire-deploy: Join token 600s TTL — expires if SPIRE download from GitHub is slow. Bootstrap cert fetch always errors (expected fallback to IPA CA).
