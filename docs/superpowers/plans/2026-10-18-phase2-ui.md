# Phase 2 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a PatternFly 6 React SPA for arbiter-hub that follows freeipa-webui modern patterns, serving SOC analysts (dashboard) and platform admins (estate management).

**Architecture:** Vite+React 18+TypeScript SPA in `ui/` directory. RTK Query services call the FastAPI backend at `:8400` via Vite proxy (dev) or nginx reverse proxy (prod). Redux Toolkit store manages global state (routes, alerts). Pages follow the freeipa-webui list-page pattern: TitleLayout → ToolbarLayout → Table → Modals. PF react-topology for federation graph.

**Tech Stack:** React 18, TypeScript 5, Vite 6, PatternFly 6, Redux Toolkit + RTK Query, react-router 7, @patternfly/react-table 6, @patternfly/react-topology 6, Vitest, nginx (prod container)

**Spec:** `docs/superpowers/specs/2026-10-18-phase2-ui-design.md`

## Global Constraints

- PatternFly 6.x — no PF5 or earlier components
- React 18.x — no React 19 features
- TypeScript strict mode
- Product name: "Red Hat Arbiter" in all UI text
- Red Hat hat logo SVG in masthead
- All tables: search, filter, sortable columns, pagination, bulk select per freeipa-webui pattern
- Sort: every PF Table column sortable (client-side for PoC). Default sort: newest first for timestamps, alphabetical for names
- Polling: 30s dashboard, 60s list pages — via RTK Query `pollingInterval`
- No authentication (PoC)
- State colors: healthy=green, registered=blue, attesting=cyan, stale=orange, failed=red, under_remediation=purple, revoked=grey

## Review Focus

1. **Invalid state transition buttons** — user clicks "Attest" on a workload in `revoked` state. UI must disable the button; if server returns 409, show inline error, don't crash.
2. **Empty API responses** — `/workloads` returns `{"items": [], "total": 0}`. Dashboard donut chart, workloads table, and all dependent components must render empty states, not error.
3. **Polling during modal** — user has "Add Workload" modal open, 30s poll fires and refreshes the list. Modal must not close or lose form state. (Task 5: modal state is local React state, independent of RTK Query cache updates — verify by keeping modal open for >30s during manual test in Step 6.)
4. **Backend health unavailable** — `/backends` returns a backend with `healthy: false`. Dashboard card must show red status, not crash on missing fields.
5. **Long ipa_principal strings** — principal like `host/very-long-hostname.subdomain.example.com@VERY.LONG.REALM.COM` must truncate in table cells with tooltip, not break layout.
