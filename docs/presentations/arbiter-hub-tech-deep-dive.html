The Problem: Fragmented Attestation

Manual Correlation

Operators cross-reference Keylime quotes, Cosign signatures, and Falco alerts across separate dashboards

Compliance Gaps

No unified audit trail linking hardware root-of-trust to runtime behavior for compliance reporting

Slow Response

Minutes to hours between detecting a runtime violation and revoking workload trust

  • TPM boot attestation runs independent of container image verification
  • Runtime behavior monitoring has no link to supply-chain signing
  • Each tool produces its own verdicts in its own format
  • No single answer to: “Should this workload be trusted right now?”

Multi-Backend Attestation

Each workload declares a backend_types array. The composite /attest endpoint runs all registered backends in parallel.

Keylime

TPM 2.0 quotes + IMA log integrity via mTLS to Verifier API

Cosign

Container image signature verification via cosign binary subprocess

Falco

eBPF runtime behavior monitoring via health endpoint polling

Trustee

Confidential VM attestation evidence via internal KBS API

Rekor

Transparency log inclusion proofs via HTTPS API

Verdict Logic

# Parallel execution, FAIL-trumps-UNAVAILABLE backend_types: ["keylime", "cosign", "falco"] # Any FAIL → composite FAIL (workload untrusted) # All PASS → composite PASS (workload trusted) # UNAVAILABLE only if no backend returned FAIL or PASS

Workload State Machine

7-state lifecycle governing workload trust. All transitions are recorded in the audit log with actor attribution.

REGISTERED
→
ATTESTING
→
HEALTHY
StateMeaningTransitions To
REGISTEREDEnrolled, never attested→ ATTESTING
ATTESTINGAttestation in progress→ HEALTHY, FAILED
HEALTHYLast attestation passed→ ATTESTING, STALE, REVOKED
STALETTL expired without re-attestation→ ATTESTING, FAILED
FAILEDAttestation failed→ UNDER_REMEDIATION, REVOKED
UNDER_REMEDIATIONActive remediation→ ATTESTING
REVOKEDTrust permanently withdrawnTerminal — no transitions

Revoked is terminal by design. To re-enroll: delete the workload and register again (creates a new audit trail).

Data Model

PostgreSQL + SQLAlchemy 2.0

Async engine (asyncpg), JSONB for flexible metadata, ARRAY for backend_types. UUID primary keys. Indexed on workload_id + created_at.

Audit Immutability

BEFORE UPDATE/DELETE triggers on audit_log table prevent modification or deletion of records.

Alembic Migrations

Schema managed by Alembic. Runs in ephemeral container on same podman network before API starts.

Cosign + Sigstore Integration

Container image signature verification as an attestation backend. Supply-chain trust anchored to cosign keypairs.

cosign sign --key cosign.key --tlog-upload=false IMAGE
→
Signature pushed to registry
→
cosign verify --key cosign.pub --insecure-ignore-tlog IMAGE
→
PASS / FAIL verdict

Backend Implementation

class CosignBackend: def __init__(self, cosign_binary, public_key, insecure_ignore_tlog=False): async def verify(self, workload): artifact_ref = workload.metadata_["artifact_ref"] cmd = [self._binary, "verify", "--key", self._public_key] if self._insecure_ignore_tlog: cmd.append("--insecure-ignore-tlog") cmd.append(artifact_ref)

Deployment Notes

  • Cosign v2.4.1 binary mounted into API container at /usr/local/bin/cosign
  • Public key at /etc/arbiter/cosign/cosign.pub
  • --tlog-upload=false for private/demo signing without Rekor transparency log
  • --insecure-ignore-tlog on verify when signatures lack tlog entries
  • cosign v2.4.1 does NOT support the --yes flag

Falco eBPF Runtime Monitoring

Falco 0.45+ with modern eBPF probe. Custom rules detect behavioral violations in attested workloads. Alerts trigger state transitions.

Custom Rules

# /etc/falco/rules.d/arbiter-rules.yaml - rule: Reverse Shell Detected condition: spawned_process and proc.name in (bash, sh, dash) and fd.type=ipv4 output: "Reverse shell from %container.id" priority: CRITICAL - rule: Sensitive File Read condition: open_read and fd.name startswith /etc/shadow output: "Sensitive read %fd.name by %proc.name" priority: WARNING

State transitions dispatch HMAC-signed webhooks to EDA. The source plugin validates and forwards events to ansible-rulebook. Full loop completes in ~2 seconds.

Authentication Modes

OIDC (Production)

JWT validation via JWKS. Supports IPA (ahdapa) and Keycloak issuers. Claims-based role extraction.

Dev Mode

X-Caller-* headers, gated behind explicit ARBITER_AUTH_MODE=dev. Never in production.

Proxy Mode

Trusts reverse-proxy identity headers. For use behind mTLS-terminating proxy.

RBAC Roles

attestation-admin · attestation-reader · policy-editor

Key Broker Service — State-Gated Secrets

Secrets released only when a workload is in the required state with a current attestation. Row-level locking prevents races during concurrent revocation.

Workload requests secret
→
GET /kbs/v0/repo/type/tag
↓
Check: state == required_state?
↓
YES →
Decrypt + release
NO →
403 Forbidden

Encryption

AES-256 encryption with key loaded from ARBITER_KBS_ENCRYPTION_KEY_FILE. No fallback to zero-key (startup error if missing).

Scope Filtering

Secrets scoped to specific workloads via workload_scope. Prevents cross-workload secret access.

Race Protection

Row-level SELECT FOR UPDATE on secret retrieval. Prevents release during concurrent revocation.

Security Model — STRIDE Assessment

Full STRIDE threat analysis performed. 6 critical findings identified and resolved across Phases 1–2.5.

Spoofing — Resolved

  • OIDC JWT validation with JWKS caching
  • X-Caller-* headers only in explicit dev mode
  • CSRF Origin validation on state-changing methods

Tampering — Mitigated

  • Audit log protected by DB triggers (no UPDATE/DELETE)
  • OCI reference regex on artifact_ref
  • --key path prefix validation

Repudiation — Resolved

  • All actions attributed to JWT-verified principal
  • Append-only audit with actor, action, target, detail

Info Disclosure — Mitigated

  • KBS key startup error (no zero-key fallback)
  • CORS restricted to explicit origins

Denial of Service — Resolved

  • slowapi rate limiting on all endpoints
  • 30s timeout on cosign subprocess calls

Elevation of Privilege — Resolved

  • RBAC roles from JWT claims (no implicit admin)
  • KBS port restricted to internal network

Remaining: input length validation on string fields (MEDIUM), DB password in default config (HIGH — vault in production).
