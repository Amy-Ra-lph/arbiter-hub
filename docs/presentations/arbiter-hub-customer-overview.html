What Is Arbiter Hub?

A federation attestation control plane that answers one question across your entire infrastructure:

“Should this workload be trusted right now?”

Federate, Don't Replace

Three Pillars of Trust

Hardware Root of Trust

TPM-based boot attestation via Keylime. Cryptographic proof of system integrity from power-on, with Integrity Measurement Architecture (IMA) for file-level verification.

Supply Chain Verification

Container image signature verification via Sigstore and cosign. Transparency log inclusion proofs confirm images were built by authorized pipelines and have not been tampered with.

Runtime Behavior

eBPF-based system call monitoring via Falco. Detects reverse shells, unauthorized file access, and unexpected processes in real time, not after a scheduled scan.

Trust Lifecycle

Seven states govern workload trust. Continuous re-attestation keeps healthy workloads trusted. Revocation is permanent.

Healthy (Trusted)

All attestation backends report PASS. Workload has access to secrets and resources. Continuous re-attestation on configurable TTL.

Failed (Untrusted)

One or more backends report FAIL. Secrets revoked. Automated remediation triggered. Network quarantine applied.

Revoked (Terminal)

REVOKED

Trust permanently withdrawn. Workload must be deleted and re-registered. No remediation path.

AI Tool Security

MCP servers (Model Context Protocol) registered as attested workloads.

Identity Bound

Each AI tool server registered with a Kerberos principal. Identity verified through IPA before tool invocation.

Image Verified

Container image signatures verified via cosign before the tool starts. Tampered images rejected at deployment.

Runtime Monitored

Falco watches for unexpected behavior: data exfiltration, privilege escalation, unauthorized network access.

Why it matters: AI tools with access to production data, customer records, and infrastructure credentials need the same attestation guarantees as any other workload. A compromised AI tool is a supply chain attack with elevated privileges.

Deployment Flexibility

Podman on RHEL

Containers managed by systemd via Podman Quadlet. No Kubernetes required. Runs on any RHEL 9+ or RHEL 10 host.

Ansible Automated

Full deployment via Ansible playbooks. Database, API, UI, monitoring, and attestation backends provisioned in one run.

OpenShift Compatible

Same container images deploy on OpenShift. Attestation backends reach Keylime and Falco agents on host nodes.

UBI 10 Base Images

Built on Universal Base Image 10. Signed with cosign. Published to container registry.

PostgreSQL Backend

Production-grade RHEL PostgreSQL 16. All state in the database. API nodes are stateless and horizontally scalable.

OpenTelemetry

Traces, metrics, and structured events. Prometheus endpoint at /metrics. OCSF-formatted security events.
